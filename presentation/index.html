Comprehende.
Keep yourself in the loop.

Comprehende is a local review assistant for git diffs. It groups a diff by review concern and shows the groups in a fixed UI.

AI writes faster than we can read.

When we accept generated code with no view of our own, comprehension debt grows. Nobody chooses it, and it stays hidden until something breaks.

Comprehende gives you a view to hold against the diff. You hand off the how and keep the why and the what.

Read concerns, not files A to Z.

db/seed.ts

Three parts. Each does one job.

The skill groups

It reads the digest, one line per file, and writes the title, the groups, the summaries, and the look-for notes. It never copies patch text.

Git shows the diff

Serve reads the diff from git in your repo at serve time. The review file holds interpretation only.

The UI stays fixed

Same screens for every review. Only the data changes. Serve runs it locally, export writes a static site.

What the UI shows.

A reading order

Groups list in suggested order. Foundations first, mechanical work last. Mixed work splits into parts.

Why, what, look for

Each group states why it exists and what it changes. Look-for notes name what a first read misses, with cited sources.

Full context

Full files, blame, commit messages, and the sources the skill read sit one click away. Links reopen the same view.

Honest coverage

Validate checks that every hunk sits in a group. Ungrouped hunks show as unassigned. Lockfiles get their own bucket.

Goals and non-goals.

Goals

  • Live git wins. The review file is interpretation only.
  • Same UI every time. Only the data changes.
  • Plain wording a tired reviewer can read.
  • Local first. No hosted service needed.

Non-goals

  • No auto-approve and no review gate.
  • It does not replace the diff.
  • No forge lock-in. Plain git only.
  • It never invents a motive from the patch.

Install in two minutes.

# add the skill, once npx skills add matemolnar8/comprehende # inside the repo under review npx comprehende@0.10.0 serve --data review.json

Needs

  • Node 24, git, and a work tree.
  • Run every command inside the repo under review.
  • Full flow is review, validate, serve, export.
