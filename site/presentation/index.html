Comprehende

Pay attention where it counts.

The agent writes the how. Comprehende gives you the why and the what.

Agents write faster than we can understand

  • A pull request lists files in alphabetical order. That is how git stores them, not the order in which a change makes sense.
  • The tests pass and the code looks clean, so we approve it without understanding it. That is cognitive surrender.
  • Each change we do not understand adds comprehension debt. Nobody chose it and nobody can see it.
  • The debt comes due in an incident or a long debug session.

From surrender back to offloading

surrender→offloading

Surrender

  • The agent decides what the change is and you take its word.
  • You have no view of your own to compare with the code.
  • The pull request is approved and the understanding is gone.

Offloading

  • The agent still writes the how. That part stays offloaded.
  • Comprehende gives you the why and the what for each group of hunks.
  • You check that view against the live diff. The understanding stays with you.

A review assistant for any git diff

Your coding agent reads the diff and groups the hunks by review concern. Groups that belong to one story sit together. A fixed local web UI shows them next to the real diff from git.

How it works

  1. The CLI indexes base...head and writes a skeleton. One entry per changed file, hunk refs, stub prose.
  2. The agent fills the interpretation. Title, groups, why, what, things to check, sources. It never invents a hunk ref.
  3. Validate, then serve or export. Every ref must resolve in live git. The UI reads the diff from git when you open it.

Start with the whole change

  • AWhy and what. Your view of the change, before any diff.
  • BThings to check. Where the code and a source do not agree, with a citation.
  • CGroups in reading order. Work that could have been its own pull request gets its own part.

Then one group at a time

  • AOne review concern. Each group says why it exists and what it does.
  • BAttention. The one call only you can make: a contract, a tradeoff, a product call, or a risk. Most groups have none.
  • CThe real diff. From live git, with one line on what changed in each file.

Go past the diff

  • AOpen file. The full file at base or head, one click from any hunk.
  • BBlame. Each run of lines names its commit, author, and date.
  • CIn this review. Lines from commits in this change show the commit summary.

Also in the UI

  • Focus and notes. In a long hunk, the lines that matter open first, with lettered notes on single lines.
  • Ask agent. Up to two questions per group about why the code is this way. One click opens one in Claude Code, Codex, Cursor, or T3 Code.
  • Sources. The tickets, pull request comments, commits, and agent transcripts the agent read, each with a gist. Citations in the text link to them.
  • Refresh. New commits keep the old groups. The What changed page shows the delta.
  • Mechanical groups. Renames and generated output sit apart, so you know what to skip.
  • Images. Side by side, slider, or pixel diff.
  • Keyboard. [ ] move between groups, j k between files, v marks viewed, o opens the overview. Every view has a URL you can share.
  • Any screen. The same review on a phone, in light or dark.

Goals

  • Accuracy. Live git wins. The review file holds interpretation only and never stores diff text.
  • Coverage. Every hunk is in a group, or validate fails.
  • Fixed UI. The same UI every time. Only the data changes.
  • Local. No hosted service and no account.
  • Plain words. Simplified Technical English in the UI and in the generated text.

Non-goals

  • Review for you. It gives you a view to hold against the diff. Understanding the change is still your job.
  • Judge. No approve or reject and no score. Things to check are claims, and an attention names a call for you. Neither is a verdict.
  • Replace git. No stored patches and no second source of truth.
  • Know your forge. GitHub, GitLab, Bitbucket, and Jira live in the skill, not in the tool. The core is plain git.
  • Generate UI. The model never draws a screen.

Install and use

# once, in any repo
npx skills add matemolnar8/comprehende

# in your coding agent, name what to review
/comprehende PR 154 # in a stack, only its own layer
/comprehende the changes from the last turn
/comprehende feature/auth against main

The agent writes review.json and prints a local URL. Needs Node.js 24+ and git, on macOS, Linux, or Windows. The diff never leaves your machine.
